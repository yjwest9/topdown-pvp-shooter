## 0. 기본

- 게임명: TOP SOLDIER (탑솔져). 패키지 `com.yjseo.topsoldier`.
- 장르: 2D 탑다운 실시간 PvP 슈터. 핵심은 **PvP**. PvP 없는 방향은 검토 대상 아님.
- 원작 스페셜솔져(웰게임즈/넥슨, 2015-03 ~ 2020-07, 3D 모바일 FPS)에서 영감. 이름/그래픽/로고는 쓰지 않는다.
- 배포: Android, Google Play. Mac이 없어서 iOS 제외. 웹(크롬)은 테스트용 클라이언트.
- 개인 프로젝트. 최종 발표 2026-10-22.

## 1. 과제 필수 요건

Open API 1개 이상 / 푸시 알림 1개 이상 / Firebase / REST·JSON / MVVM / 테스트·배포(APK, 스토어).

- **Open API (확정, 2026-10-07)**: 한국천문연구원 특일정보 API(공휴일). 공휴일에 매치 보상 2배 이벤트. 푸시로 이벤트 시작 알림. 키는 `--dart-define`, 웹은 CORS로 실패 시 이벤트 없음 처리.

## 2. 시점과 조작

- **회전 시점**: 카메라가 플레이어 방향으로 회전해서 화면 위쪽 = 내 정면. 화면에서 플레이어는 세로 66% 지점. 나침반 HUD로 북쪽 표시.
- 왼쪽 화면 아무 곳: 떠다니는 조이스틱(반경 50px)으로 이동. 이동은 정면 기준(위로 밀면 앞으로).
- 조이스틱을 **바깥 원(80px)까지 끌면 달리기**. 달리기 버튼은 따로 없다.
- **달리기는 앞쪽(정면 ±45°)으로 밀 때만** [잠정, 체험 후 결정]. 키보드도 Shift + 앞(W) 방향일 때만.
- 달리는 중 사격 대상이 조준선에 들어오면(자동 무기) 또는 사격 버튼을 누르면 걷기로 바뀌며 사격. 사격이 끝나고 달리기 입력이 계속 있으면 다시 달린다.
- 오른쪽 화면 드래그: 시점 회전. 가로 이동량 × 0.004875 rad × (감도/5). (2026-10-12: 너무 빨라서 전체를 0.65배로 내림. 예전 0.0075 기준이면 새 감도 10 ≈ 예전 6.5)
- **시점 감도 1.0~10.0, 소수 한 자리 단위**(5.7, 3.7 …), 기본 5.0. 설정 화면에서 바꾸고 기기에 저장(2026-10-12).
- 버튼: 점프, 앉기(토글), 사격(수동 발사 무기일 때만 표시), 재장전. 오른쪽 위에 무기 슬롯 버튼(주무기 / 보조무기, 근접은 나중).
- **발사 방식은 수동/자동 2가지.** (2026-10-12 변경) 무기마다가 아니라 **주무기 칸·보조무기 칸에 하나씩**(설정 화면, 기기에 저장). 기본은 둘 다 자동. 무기를 바꿔도 칸 설정을 따른다. (예전: 무기별, 저격만 수동)
  - 자동: 조준선 ±0.14 rad 안, 사거리 안, 시야가 막히지 않은 적이 있으면 자동 사격.
- 고정 시점(북쪽이 위)은 쓰지 않는다.
- **화면은 가로 고정**(Android `sensorLandscape`, 좌우 뒤집기만 허용). 세로 플레이 없음.
- 회전 시점은 에뮬레이터 체험 후 계획대로 유지하기로 재확인(2026-10-02).
- 웹/PC 디버그 키: WASD 이동, ←→ 회전, Space 점프, C 또는 Ctrl 앉기, Shift 달리기, ↑ 사격, 1~9·0 주무기 선택, Q 주·보조 교체, R 재장전. (1~0은 개발용. 실제 로드아웃은 홈 화면에서 미리 정한다.)
- 사격 버튼을 누른 채 끌면 회전(오른쪽 드래그와 같은 감도).

## 3. 자세

| 자세 | 이동 속도 | 탄 퍼짐 | 사격 | 비고 |
|---|---|---|---|---|
| 서서 정지 | - | ×1.0 | 가능 | |
| 걷기 | 220px/s (×1.0) | ×2.5 | 가능 | 속도 30px/s 넘으면 이동으로 판정 |
| 달리기 | ×1.5 | - | **불가** | 달리기를 시작하면 앉기 해제 |
| 앉기 | ×0.45 | ×0.4 | 가능 | 피격 반경 ×0.7 |
| 점프(0.5초) | ×1.2 | ×4.0 | 가능 | 낮은 상자 충돌 무시, 재점프 대기 0.75초 |
| 상자 위 | 자세 따름 | 자세 따름 | 가능 | 위에서 앉기 가능 |

- **달리는 중 앉기**: 바로 앉고 달리기는 꺼진다. 이동 입력은 유지돼서 앉은 속도로 계속 간다. 달리기 입력을 계속 누르고 있어도 다시 일어나지 않고, 달리기를 새로 시작해야(Shift 다시 누르기, 조이스틱을 바깥 원 밖으로 다시 빼기, 멈췄다 다시 이동) 일어나서 달린다.
- 점프가 끝날 때 몸 중심이 낮은 상자 안이면 **상자 위에 선다**. 걸어서 중심이 상자 밖으로 나가면 내려온다. 가장자리에 걸치면 미끄러져 내려온다.
- 플레이어 반경 16px.
- **병사 그림 포즈**(2026-10-14, Kenney Top-down Shooter): 무기 종류에 따라 라이플·M249·샷건 = machine, 저격총 = silencer, 권총 = gun. **재장전 중 = reload**. 그림은 바라보는 방향으로 회전, 판정 반경은 그대로. 앉기 = 그림 0.85배 + 앉기 링 유지. 점프는 기존 표시 방식(그림 크기만 맞춤). 죽음·부활 보호 중은 흐리게. 팀 구분은 그림이 아니라 **발밑 원**(나 파랑, 상대 빨강).
  - (2026-10-15) 총구 흰 선은 없앤다(그림의 총이 정면을 보여 준다). **상대도 재장전 포즈**: 상태(`states/{uid}`)에 재장전 중 여부 `rl`을 같이 보낸다(없으면 false, 옛 앱 호환).
  - (2026-10-15) 밝은 바닥에서도 보이게: HUD 버튼·무기 칸은 어두운 반투명 바탕, 글자는 그림자, 조준 점선·퍼짐 선은 어두운 테두리를 깐다.
  - (2026-10-15 변경) 병사 그림은 Kenney PNG 대신 **코드로 그린 위에서 본 실루엣 택티컬 병사**(8장). 포즈 이름과 규칙(machine·silencer·gun·reload·stand, 앉기 0.85배, 발밑 팀 원)은 그대로. 바닥에서 잘 보이게 밝은 테두리(캐릭터 색)와 밝은 총을 쓴다.

## 4. 엄폐물과 시야

| | 서 있음 | 낮은 상자 바로 뒤(50px 이내)에 앉음 | 점프 중 | 상자 위 |
|---|---|---|---|---|
| 높은 벽 | 시야·총알 차단 | 차단 | 차단 | 차단 |
| 낮은 상자 | 보이고 맞음 | **안 보이고 안 맞음** | 보이고 맞음, 넘어감 | 보이고 맞음 |

- **양방향**: 낮은 상자 바로 뒤에 앉아 숨은 사람도 그 상자 너머로는 못 쏜다(자동 사격 안 됨, 수동으로 쏘면 상자에 박힘). 쏘려면 일어서야 한다.
- 상자 위에 있는 사람은 상자 뒤에 앉은 적을 볼 수 있고 맞힐 수 있다(쏜 사람이 상자 위면 낮은 상자 차단 무시).
- 낮은 상자는 걸어서 못 지나가고 점프로만 넘는다.
- **맵 그림**(2026-10-14, Kenney): 걸을 수 있는 곳 = 바닥 타일, 높은 벽 = 벽 타일, 낮은 상자 = 상자 그림. **높은 벽과 낮은 상자는 한눈에 구분돼야 한다**(점프·엄폐 규칙 때문에 가장 중요). 64px 타일을 70px 칸에 맞춰 늘린다. 맵 구조·판정은 그대로. 고른 타일: 바닥 `tile_07`·`tile_08`(회청색 돌, 고정 패턴으로 섞음), 높은 벽 `tile_171`(주황 테두리 + 어두운 속), 낮은 상자 `tile_129`(나무 상자). 높이 차이를 더 키우려고 벽은 긴 그림자, 상자는 짧은 그림자를 깐다. 맵 전체는 게임에 들어올 때 한 장의 그림으로 미리 그려 둔다(31×31칸을 매 프레임 그리지 않으려고).
- **시야 제한**(앞쪽 부채꼴 ±0.72 rad, 640px + 주변 80px)은 기본 PvP에서는 끈다. 좀비전 등 모드에서 사용.
- 튜토리얼(훈련소)에서 이 규칙을 단계별로 가르친다.

## 5. 전투 판정

- 총알은 즉시 판정이 아니라 날아간다: 750px/s.
- 명중 판단은 쏜 사람 폰에서 한다. 피해 적용은 Realtime Database 트랜잭션(8장).
- **미스**: 총알이 몸에 닿으면 굴린다. `미스 확률 = 5% + 상대 회피율 − 내 명중률`, 최소 0%, 최대 20%. **점프 중인 상대는 미스 +10%p** [잠정](점프 회피, 상한 20%는 그대로). 미스면 총알이 통과하고 "MISS" 표시.
- **크리티컬**: `무기 크리티컬 + 캐릭터 크리티컬`, **상한 30%** [잠정, 설정값]. 배율은 무기별(라이플·저격 ×2, 샷건 ×1.5, 권총 ×2).
- 2D라 헤드샷은 없다. 크리티컬이 그 역할.
- (2026-10-15) **총알 = 팀 색 예광탄**: 흰 중심 + 둘레 색(내 총알 하늘색, 상대 총알 빨강). 누가 쏜 총알인지 바로 보이게.
- (2026-10-14) 명중·크리는 **쏜 사람** 캐릭터, 회피는 **맞는 사람** 캐릭터. 상대 캐릭터는 방의 `players/{uid}`(character, characterLevel)에서 읽는다. 봇·표적은 기본 병사 +0.
- **성장 격차 상한**: 완전히 키운 유저 vs 신규 유저의 체감 차이가 총알 약 2발 이내가 되도록 수치를 잡는다. 테스트로 검증.
  - 기준: 표준형 라이플, 기대 발수 격차 ≤ 2.0
- 봇 조준: 상대 속도를 0.35초 지연된 평균으로 예측(갑자기 방향을 바꾸면 빗나가게).

## 6. 무기

- 무기는 **데이터 표의 한 줄**. 로직은 공통.
- 슬롯: 주무기 1 + 보조무기 1. 무기마다 남은 탄을 기억한다(바꿨다 돌아와도 장전 안 됨). 이후 근접(칼), 투척(수류탄) 추가 예정.
- **이름**(2026-10-12): 실제 총기명. 군용 제식명은 그대로, 제품 모델명은 그대로 또는 살짝 변형. 총기 회사 로고·각인은 그리지 않는다. 이름은 데이터(`balance.dart`의 `name`)로만 관리해서 상표권자 요청이 오면 거기만 바꾼다.
  - 표준형 K2 / 연사형 FAMAS / 정밀형 M14 / 중기관총형 M249 / 볼트액션 TRG-42 / 반자동 저격 SVD / 경량 저격 VSS / 펌프 M870 / 자동 샷건 M1014 / 더블배럴 SAWED-OFF / 권총 M9
  - 다음 추가 후보: AKM(고데미지 라이플), M4A1, AWM 계열
- **보유·구매**(2026-10-12): 기본 지급 K2(주무기)·M9(보조). 나머지 9종은 E등급을 20,000골드에 구매. 보유 무기는 개체 단위로 저장(7장, 나중에 합성용)하되 지금 화면에서는 같은 무기를 한 번만 살 수 있다. 강화·합성·D등급은 아직(버튼도 없음).
  - `users/{uid}/weapons/{id}` = { weaponId, grade: "E", level: 0, acquiredAt }, `users/{uid}/loadout` = { primary, secondary } (개체 id). 기존 유저도 loadout이 없으면 기본 무기 2개를 지급한다.
  - 구매는 `users/{uid}` 트랜잭션 하나로 골드 차감 + 무기 생성(골드 부족·이미 보유면 아무것도 안 바뀜).
  - PvP·봇전·훈련소 모두 로드아웃 무기로 시작. 숫자키 1~0 무기 변경은 훈련소에서만(디버그).

| 반자동 저격 | 950 | 10 | 2.4 | 0.01 | 1 | 0.9 | 수동 |

- 퍼짐 = 기본 퍼짐 × 자세 배율 × 이동 중 배율. 단발 무기는 조준선 ±퍼짐 안에서 랜덤.
- 샷건 퍼짐은 부채꼴 전체 폭. 펠릿이 그 폭에 고르게 퍼진다. 자세 배율은 샷건에도 적용.
- 이동 중 배율(moveSpreadScale): 경량 저격만 0.5, 나머지 1.0. 걷기·점프 중에만 곱한다.
- 탄이 0이 되면 자동 재장전. 수동 재장전은 탄이 가득이면 무시. 무기를 바꾸면 재장전 취소.
- 사격 버튼을 누른 채 끌면 회전한다(오른쪽 드래그와 같은 감도 공식).

## 7. 성장: 등급, 강화, 합성 (원작식)

- **등급은 지금 E(최하), D 두 단계만.** 이후 C, B…로 확장 가능한 구조.
- **등급과 강화는 데미지 배율 하나만 올린다.** 연사/사거리/탄창 등 무기 개성은 그대로.
  - E+0 100%, 강화 1단계당 +2%, E+5 110% / D+0 110%, D+5 120%.
- **강화** +1~+5: 골드 소모, 단계가 오를수록 성공률 하락. **실패해도 골드만 잃고 무기는 안 깨진다.**
  - (2026-10-12) 단계별 비용 / 성공률: +0→+1 2,000 G / 90%, +1→+2 4,000 / 80%, +2→+3 6,000 / 70%, +3→+4 8,000 / 60%, +4→+5 10,000 / 50%. 수치는 balance.dart.
  - 데미지 배율은 `gradeMultiplier(등급, 단계)`(E+0 100% ~ E+5 110%). 내가 쏘는 총알에 장착 무기의 배율이 들어간다(빠른 대전·친선전·봇전·훈련소 모두). 봇은 E+0.
  - 저장: 확률은 폰에서 한 번만 굴리고, `users/{uid}` 트랜잭션 안에서는 "골드 ≥ 비용이고 무기가 아직 그 단계일 때만" 골드를 빼고 성공이면 +1(다시 돌아도 결과가 같고 두 번 적용되지 않음). DB 규칙: 보유 무기 level은 그대로 또는 정확히 +1, 새 무기는 0, 종류는 못 바꿈.
  - 무기 화면 보유 무기 상세에 강화 영역("+2 → +3", 비용, 성공률, 데미지 변화). 무기 이름 옆 "+N"(목록·홈·게임 HUD).
  - D등급과 합성은 아래 합성 항목.
- **합성**(2026-10-21 구체화, 사용자 결정): 같은 계열(라이플·저격·샷건) **E등급 +5 무기 2개(서로 다른 개체)** → 기준 무기(먼저 고른 것)가 **같은 weaponId 그대로 D+0**이 되고 재료 무기는 삭제된다. 비용 15,000 G(`mergeCost`, balance.dart).
  - 보조(권총)는 계열에 1종뿐이고 중복 구매가 막혀 있어 합성 대상이 아니다(이번 범위 밖).
  - **장착 중인 무기는 재료로 고를 수 없다**(기준으로는 가능).
  - D등급 데미지 배율은 `gradeMultiplier` 그대로(D+0 110%), D등급 강화도 기존 강화 그대로 +5까지(D+5 120%).
  - 저장: `users/{uid}` 트랜잭션 하나로 "골드 ≥ 비용, 두 무기가 아직 E+5이고 같은 계열이고 재료가 장착 중이 아님"일 때만 골드 차감 + 기준 무기 grade D·level 0 + 재료 삭제. 조건이 안 맞으면 아무것도 안 바뀐다(다시 돌아도 두 번 적용 안 됨). DB 규칙: 보유 무기 grade는 E+5 → D+0 한 가지 변경만 허용(그 밖의 등급 변경은 막음), 새 무기는 E+0, 종류는 못 바꿈, 삭제는 허용.
  - 무기 화면 보유 무기 상세, E+5이고 합성 가능한 계열이면 강화 영역 아래에 "합성" 영역: 같은 계열 E+5 재료 목록(장착 중은 비활성) → 하나 고르면 확인 창 → 결과. 이름 옆 표시는 E등급 "+N", D등급 "D+N"(목록·홈·게임 HUD 공통).
- D등급 다이아 직접 구매 버튼은 만들되 결제 연동 전까지 비활성.
- 보유 무기는 개체 단위로 저장(같은 무기 여러 개 보유 가능): `users/{uid}/weapons/{id}` = { weaponId, grade, level }.

## 9. 재화와 경제 [수치 잠정, 전부 설정값으로]

- **골드**: 플레이로 획득. 무기 구매, 강화, 합성.
- **다이아**: 지금은 골드 환전으로만 획득(나중에 결제 추가). 캐릭터, D등급 직접 구매 등.
- 환전: **골드 100,000 → 다이아 100** (1다이아 = 1,000골드). 골드 → 다이아 한 방향만.
- 매치: 승리 5,000 / 패배 2,500 / 킬당 200. 무승부는 패배와 같게.
  - (2026-10-12) 봇전은 50%, 훈련소는 보상 없음, 공휴일 이벤트 중엔 2배(골드·경험치 모두). 수치는 balance.dart.
  - (2026-10-12) **보상은 빠른 대전(실시간)과 봇전만.** 방 만들기·코드 입장(친선전)은 보상 없이 전적만 저장(친구끼리 짜고 보상 쌓기 방지). 전적을 보는 화면은 아직 없다.
  - (2026-10-12) **빠른 대전 중 나가기 = 패배**: "지금 나가면 패배로 기록됩니다" 확인 후 1판 패배(보상 0)로 저장. 남은 사람은 승리(보상 받음). 클라이언트 조작은 아직 못 막는다(나중에).
  - (2026-10-21 사용자 결정, 이전엔 "앱 강제 종료로 나가는 경우는 아직 못 막는다") **빠른 대전 중 앱을 강제 종료해 나간 경우도 패배로 기록한다.** 빠른 대전이 시작되면(방 meta에 끝나는 시각이 생길 때) `users/{uid}/activeMatch = { matchId, startedAt }`(서버 시간)을 쓰고, 결과를 정상 저장하거나 "나가기 = 패배"로 저장할 때 같은 트랜잭션에서 지운다. 앱을 다시 켰을 때 `activeMatch`가 남아 있으면 그 판을 패배(보상 0, 전적 1패)로 한 번 저장하고 지운다(`lastMatchId`로 두 번 저장되지 않음, 이미 저장된 판이면 표시만 지움). 홈에 안내 한 번: "지난 대전을 끝내지 않고 나가 패배로 기록되었습니다." 봇전·친선전·훈련소는 대상이 아니다. 매치 중 앱이 살아 있는 채 연결만 끊겼다 돌아오는 경우(재연결·유예)는 바꾸지 않고, `activeMatch`는 앱이 다시 시작될 때만 확인한다. 남은 사람 쪽 처리(이미 상대 이탈 승리)와 이탈 페널티는 이번 범위 밖. 한계: 결과를 끝까지 봤는데 저장이 실패(오프라인)하면 `activeMatch`가 남아 다음 실행에서 패배로 기록될 수 있다.
- **경험치·레벨**(2026-10-12): 승리 100 / 패배 50 / 킬당 10 EXP. 다음 레벨까지 필요량 = 100 + 50 × (현재 레벨 − 1). 한 번에 여러 레벨을 넘을 수 있다.
- **프로필**(2026-10-12): Firestore 대신 Realtime Database `users/{uid}`에 둔다(DB 하나로 관리). 첫 실행에 닉네임(2~12자, 한글·영문·숫자) 입력, 홈에서 닉네임을 눌러 변경. 임시 닉네임 "Soldier1234"는 입력 창의 기본값으로만 쓴다. 매치 보상은 트랜잭션으로 저장하고 `lastMatchId`로 같은 결과가 두 번 더해지지 않게 한다.
- 보상형 광고: 10,000골드, **1시간 쿨타임(서버 시간 기준)**. 하루 횟수 제한은 없다(설정값도 두지 않음, 2026-10-14).
  - (2026-10-14) 저장은 `users/{uid}/lastAdAt`(서버 시간 ms). 골드 +10,000(`ServerValue.increment`)과 lastAdAt(`ServerValue.timestamp`)을 update 한 번으로 같이 쓴다. 보상은 광고 SDK의 보상 콜백(onUserEarnedReward)이 왔을 때만. 닫기만 하면 없음.
  - DB 규칙: lastAdAt은 새 값 == now이고, 이전 값이 없거나 now − 이전 값 ≥ 3,600,000일 때만(값 그대로 두는 쓰기는 허용). 3,600,000은 balance.dart 값과 같아야 한다.
  - 남은 시간 표시는 `.info/serverTimeOffset`으로 서버 시간을 추정해 계산.
- **환전**(2026-10-14): 상점의 [100 다이아 받기 — 100,000G] 버튼 하나, 한 번에 100다이아. 확인 창 뒤 트랜잭션(골드 확인 → −100,000, +100다이아). 골드가 모자라면 버튼 비활성.
- 가격: E등급 무기 20,000 / 강화 2,000 → 10,000(단계별) / 합성 15,000 / 캐릭터 ~~300~~ **100다이아**(2026-10-14), 캐릭터 강화는 무기 강화와 같은 골드.
- 강화 확률도 폰에서 굴리므로 조작 가능성은 재화와 같은 한계로 인정(2026-10-12).
- 재화를 클라이언트가 쓰는 구조라 조작 가능성은 인정. DB 보안 규칙으로 본인 문서만 수정 가능하게(level·exp·gold·diamond는 0 이상 숫자).

## 12. 모드와 매치

- 우선순위: **PvP 1대1** → 훈련소(봇 + 튜토리얼) → PvP 2대2 → 좀비전(시야 제한) → 3대3.
- **친선전 2대2**(2026-10-21 사용자 결정, 이전엔 "PvP 2대2(빈자리 봇)"): **친선전(방 만들기·코드 입장)에서만.** 빠른 대전 2대2와 빈자리 봇은 범위 밖. 1단계는 대기실과 팀 이동까지, 게임 화면의 4인 처리는 2단계.
  - 방 만들기에서 인원 1대1 / 2대2를 고른다(기본 1대1). 2대2를 고르면 맵은 outpost 고정(duel 칩 비활성). 방 meta `teamSize`(1 또는 2). 없으면 1(기존 방·옛 앱 호환).
  - 정원 = teamSize × 2. 입장하면 인원이 적은 팀으로 자동 배정, 같으면 A.
  - 대기실은 A팀·B팀 칸을 나눠 보여 준다(칸마다 teamSize 자리, 빈자리 표시). 1대1 방도 같은 화면 구조.
  - 팀 이동: 상대 팀에 빈자리가 있으면 "이 팀으로" → 내 `players/{uid}/team`만 바꾼다.
  - 자리 바꾸기: 상대 팀 사람 옆 "자리 바꾸기" → 그 사람에게 수락/거절 창 → 수락하면 두 사람의 팀이 서로 바뀐다. 요청은 한 번에 하나, 10초 안에 응답이 없으면 자동 취소, 요청한 사람이 취소할 수 있다. 각자 자기 `players/{uid}` 아래에만 쓴다: 요청은 내 노드에 `swapTo`(상대 uid)와 `swapAt`(서버 시간, 10초 계산용), 수락은 상대가 자기 `team`을 바꾸고 `swapAccepted`(요청자 uid)를 쓰면 요청자가 보고 자기 `team`을 바꾼 뒤 요청을 지운다. 거절은 `swapDeclined`(요청자 uid)로 알린다(요청자가 보고 지움).
  - 시작은 방장만, 두 팀 인원이 모두 teamSize이고 처리 중인 자리 바꾸기가 없을 때. 1대1 방은 지금처럼 시작된다.
  - **2단계: 게임 화면 4인 처리**(2026-10-21 사용자 결정, 1단계의 "2대2 준비 중" 비활성을 이걸로 대체).
    - 승리: 3분 동안 **팀 킬 합계 12킬 선취**(`killsToWin2v2`, balance.dart). 시간 종료 시 팀 점수 비교, 같으면 무승부. 1대1은 7킬 그대로.
    - 스폰: 팀 스폰 3개 중 **가장 가까운 적과의 거리가 가장 먼 곳**. 시작은 같은 팀 사람끼리 uid 순서로 먼 순서대로 한 곳씩(겹치지 않게), 부활은 아군이 이미 서 있는 스폰을 건너뛰고 다음으로 먼 곳.
    - 아군 사격: 아군에게는 피해·맞힘 표시·맞힘 소리가 없고 총알은 아군을 통과한다.
    - 표시: 아군 이름표·발밑 원은 파랑, 적은 빨강. 미니맵에 아군을 파란 점으로(적 표시는 지금 규칙 그대로, 안 보임).
    - 이탈: 한 명만 나가면 계속(2대1). 한 팀이 모두 나가면 남은 팀 승리(기존 상대 이탈과 같은 유예 `stuckGraceMs`). 결과를 meta에 기록하는 "마무리 담당"은 방장이 연결돼 있으면 방장, 아니면 연결된 사람 중 **uid가 가장 작은 사람**(방장이 나가도 매치가 끝난다). 담당이 아닌 사람은 기존처럼 `hostEndGraceMs` 뒤 자기 화면 점수로 끝낸다. 그래서 DB 규칙에서 방 참가자가 "playing → ended"로 meta를 쓸 수 있게 한 가지만 넓혔다(방장 쓰기는 그대로).
    - 결과 화면: 팀 승패, 팀 점수(내 팀 : 상대 팀), 내 킬·데스. 친선전이라 보상 없음, 전적은 지금 친선전과 같다.

## 13. 멀티플레이와 데이터

- **Realtime Database**(asia-southeast1): 자기 상태를 초당 15회 기록, 상대 상태는 보간해서 그림.
- **판정 = DB 트랜잭션**: 맞힌 쪽이 `hp/{상대}`를 트랜잭션으로 깎는다. HP를 0 이하로 만든 요청이 킬. 점수도 트랜잭션. 죽은 쪽이 리스폰 시 자기 HP 복구. `onDisconnect`로 접속 끊김 기록.
- 클라이언트 판정이라 치트 가능 → 과제 범위에선 허용, 발표에서 서버 판정을 개선 방향으로 제시.
- RTDB 구조:
  ```
  rooms/{code}/meta     { mode, hostUid, status, map, teamSize(1|2, 없으면 1), createdAt, endsAt }
  rooms/{code}/players/{uid} { name, team, ready, connected, character, primary, secondary, swapTo, swapAt, swapAccepted, swapDeclined(자리 바꾸기, 2026-10-21) }
  rooms/{code}/states/{uid}  { x, y, a, stance, up, weapon, rl(재장전 중, 2026-10-15), t }
  rooms/{code}/hp/{uid}      (트랜잭션)
  rooms/{code}/shots/{id}    연출용
  rooms/{code}/kills/{id}    { killer, victim, weapon, crit, t }
  rooms/{code}/score         { A, B } (트랜잭션)
  matchmaking/1v1/waiting    { uid, roomId, name, t, takenBy? } (빠른 매칭 대기석)
  ```
- **매칭**(2026-10-12): 방 코드 입장은 그대로 두고 **빠른 대전 1대1**을 추가한다.
  - RTDB 대기석 하나 + 트랜잭션으로 짝짓기. 별도 서버 없음.
  - 매칭으로 만든 방은 4자리 코드가 아니라 push 키를 방 ID로 쓴다(코드 공간 낭비 방지).
  - 판정(순수 함수 `decideQuickMatch`, 판정과 쓰기는 대기석 트랜잭션 하나 안에서):
    - 비었거나 t가 15초 넘게 오래됨 → 내가 앉음(claim). 내 방, 내가 방장(A팀)
    - 내가 이미 앉아 있음 → 계속 대기(wait)
    - 남이 앉아 있고 takenBy 없음 → takenBy = 나(take). 그 방에 입장(B팀)
    - 남이 앉아 있고 takenBy 있음 → 0.5초 뒤 재시도(retry)
  - 대기하는 쪽은 5초마다 t를 갱신한다. takenBy가 생기면 대기석을 지우고 상대 입장을 기다린다. 상대가 들어오면 "상대를 찾았습니다!" 3초 카운트다운 뒤 방장이 자동 시작(시작 버튼 없음).
  - 취소: 대기석과 내 방을 지운다. 앱이 꺼지면 onDisconnect로 내 대기석과 방을 지우고, 매칭이 성사되면 그 onDisconnect를 취소한다.
  - 누가 내 자리를 잡고(takenBy) 10초 안에 방에 안 들어오면 내 방을 지우고 새 방으로 다시 찾는다.
  - 30초를 기다려도 상대가 없으면 "봇과 대전" 버튼이 나타난다. 누를 때만 매칭을 취소하고 보통 난이도 봇전으로 간다(자동으로 넘어가지 않음).
  - 방 정리: 마지막 사람이 나가면 방 전체를 지운다(빠른 매칭 방, 코드 방 둘 다). 나갈 때 내 onDisconnect도 취소한다(안 하면 나중에 끊길 때 `connected=false`를 써서 빈 방이 다시 생긴다).
  - DB 규칙: 대기석은 비었거나·내 것이거나·t가 15초보다 오래됐을 때만 새로 앉기. takenBy는 비어 있을 때 한 번, 값은 내 uid만. 삭제는 uid가 나일 때만. 방 전체 삭제는 그 방 참가자만.
