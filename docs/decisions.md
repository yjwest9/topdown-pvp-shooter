# 설계 결정 기록

TOP SOLDIER에서 정한 것들. 구현은 이 문서를 따른다. 바꾸려면 사용자와 합의한 뒤 이 문서부터 고친다.
`[잠정]`은 일단 이대로 가되 플레이 테스트 후 바뀔 수 있는 항목. 수치는 전부 `lib/rules/balance.dart`에 모은다.

## 0. 기본

- 게임명: TOP SOLDIER (탑솔져). 패키지 `com.yjseo.topsoldier`.
- 장르: 2D 탑다운 실시간 PvP 슈터. 핵심은 **PvP**. PvP 없는 방향은 검토 대상 아님.
- 원작 스페셜솔져(웰게임즈/넥슨, 2015-03 ~ 2020-07, 3D 모바일 FPS)에서 영감. 이름/그래픽/로고는 쓰지 않는다.
- 배포: Android, Google Play. Mac이 없어서 iOS 제외. 웹(크롬)은 테스트용 클라이언트.
- 개인 프로젝트. 최종 발표 2026-10-22.

## 1. 과제 필수 요건

Open API 1개 이상 / 푸시 알림 1개 이상 / Firebase / REST·JSON / MVVM / 테스트·배포(APK, 스토어).

## 2. 시점과 조작

- **회전 시점**: 카메라가 플레이어 방향으로 회전해서 화면 위쪽 = 내 정면. 화면에서 플레이어는 세로 66% 지점. 나침반 HUD로 북쪽 표시.
- 왼쪽 화면 아무 곳: 떠다니는 조이스틱(반경 50px)으로 이동. 이동은 정면 기준(위로 밀면 앞으로).
- 조이스틱을 **바깥 원(80px)까지 끌면 달리기**. 달리기 버튼은 따로 없다.
- 오른쪽 화면 드래그: 시점 회전. 가로 이동량 × 0.0075 rad × (감도/5).
- **시점 감도 1~10**, 기본 5. 설정에 저장.
- 버튼: 점프, 앉기(토글), 사격(수동 발사 무기일 때만 표시), 무기 교체, 재장전.
- **발사 방식은 수동/자동 2가지, 무기별로 저장.** 기본값: 라이플 자동, 저격 수동.
  - 자동: 조준선 ±0.14 rad 안, 사거리 안, 시야가 막히지 않은 적이 있으면 자동 사격.
- 고정 시점(북쪽이 위)은 쓰지 않는다.
- 웹/PC 디버그 키: WASD 이동, ←→ 회전, Space 점프, C 또는 Ctrl 앉기, Shift 달리기, ↑ 사격.

## 3. 자세

| 자세 | 이동 속도 | 탄 퍼짐 | 사격 | 비고 |
|---|---|---|---|---|
| 서서 정지 | - | ×1.0 | 가능 | |
| 걷기 | 220px/s (×1.0) | ×2.5 | 가능 | 속도 30px/s 넘으면 이동으로 판정 |
| 달리기 | ×1.5 | - | **불가** | 달리면 앉기 해제 |
| 앉기 | ×0.45 | ×0.4 | 가능 | 피격 반경 ×0.7 |
| 점프(0.5초) | ×1.2 | ×4.0 | 가능 | 낮은 상자 충돌 무시, 재점프 대기 0.75초 |
| 상자 위 | 자세 따름 | 자세 따름 | 가능 | 위에서 앉기 가능 |

- 점프가 끝날 때 몸 중심이 낮은 상자 안이면 **상자 위에 선다**. 걸어서 중심이 상자 밖으로 나가면 내려온다. 가장자리에 걸치면 미끄러져 내려온다.
- 플레이어 반경 16px.

## 4. 엄폐물과 시야

| | 서 있음 | 낮은 상자 바로 뒤(50px 이내)에 앉음 | 점프 중 | 상자 위 |
|---|---|---|---|---|
| 높은 벽 | 시야·총알 차단 | 차단 | 차단 | 차단 |
| 낮은 상자 | 보이고 맞음 | **안 보이고 안 맞음** | 보이고 맞음, 넘어감 | 보이고 맞음 |

- 상자 위에 있는 사람은 상자 뒤에 앉은 적을 볼 수 있고 맞힐 수 있다(쏜 사람이 상자 위면 낮은 상자 차단 무시).
- 낮은 상자는 걸어서 못 지나가고 점프로만 넘는다.
- **시야 제한**(앞쪽 부채꼴 ±0.72 rad, 640px + 주변 80px)은 기본 PvP에서는 끈다. 좀비전 등 모드에서 사용.
- 튜토리얼(훈련소)에서 이 규칙을 단계별로 가르친다.

## 5. 전투 판정

- 총알은 즉시 판정이 아니라 날아간다: 750px/s.
- 명중 판단은 쏜 사람 폰에서 한다. 피해 적용은 Realtime Database 트랜잭션(8장).
- **미스**: 총알이 몸에 닿으면 굴린다. `미스 확률 = 5% + 상대 회피율 − 내 명중률`, 최소 0%, 최대 20%. 미스면 총알이 통과하고 "MISS" 표시.
- **크리티컬**: `무기 크리티컬 + 캐릭터 크리티컬`, **상한 30%** [잠정, 설정값]. 배율은 무기별(라이플·저격 ×2, 샷건 ×1.5, 권총 ×2).
- 2D라 헤드샷은 없다. 크리티컬이 그 역할.
- **성장 격차 상한**: 완전히 키운 유저 vs 신규 유저의 체감 차이가 총알 약 2발 이내가 되도록 수치를 잡는다. 테스트로 검증.
  - 기준: 표준형 라이플, 기대 발수 격차 ≤ 2.0
- 봇 조준: 상대 속도를 0.35초 지연된 평균으로 예측(갑자기 방향을 바꾸면 빗나가게).

## 6. 무기

- 무기는 **데이터 표의 한 줄**. 로직은 공통.
- 슬롯: 주무기 1 + 보조무기 1. 이후 근접(칼), 투척(수류탄) 추가 예정.
- 이름은 실제 총기명 대신 가상 이름. 아래는 [잠정] 초기 수치. 밸런스 기준은 TTK = (필요 발수 − 1) × 연사 간격.

| 계열 | 종류 | 데미지 | 연사 간격 | TTK | 장점 | 단점 |
|---|---|---|---|---|---|---|
| 라이플 | 표준형 | 13 | 0.11s | 0.77s | 무난 | 특출난 점 없음 |
| 라이플 | 연사형 | 9 | 0.07s | 0.77s | 근거리 강함, 탄창 40 | 퍼짐 커서 원거리 약함 |
| 라이플 | 정밀형(반자동) | 26 | 0.28s | 0.84s | 원거리 정확 | 빗나가면 손해, 탄창 15 |
| 라이플 | 중기관총형 | 15 | 0.10s | 0.60s | 가장 빠른 킬 | 이동 ×0.75, 재장전 4s, 앉아야 정확 |
| 저격 | 볼트액션 | 90 | 1.3s | 1.3s | 크리 시 한 방 | 놓치면 끝, 이동 느림 |
| 저격 | 반자동 | 40 | 0.45s | 0.9s | 연속 사격 | 한 방 없음 |
| 저격 | 경량 | 60 | 0.9s | 0.9s | 이동 중에도 정확 | 사거리 짧음 |
| 샷건 | 펌프 | 최대 88 | 0.8s | 0.8s | 근거리 안정 | 사거리 260 |
| 샷건 | 자동 | 최대 48 | 0.28s | 0.56s | 근거리 최속 | 퍼짐 큼, 사거리 200 |
| 샷건 | 더블배럴 | 최대 110 | 0.25s | 근접 한 방 | 역전 한 방 | 탄창 2, 재장전 2.6s |
| 보조 | 권총 | 15 | 0.3s | - | 주무기 재장전 중 대안 | 약함 |

- 크리티컬 확률 초기값: 라이플 10%, 볼트액션 저격 25%, 다른 저격 15%, 샷건 10%, 권총 10%.
- 참고 기준값: 라이플 사거리 560px·탄창 30·재장전 1.8s / 저격 사거리 1100px·탄창 5·재장전 2.5s / 샷건 8펠릿·사거리 260px·탄창 6·재장전 2.2s / 권총 사거리 450px·탄창 12·재장전 1.2s. 표에 없는 값은 구현 시 제안하고 사용자 확인.
- 저격 조준 중에는 카메라가 앞쪽으로 당겨져서 스코프 역할.

## 7. 성장: 등급, 강화, 합성 (원작식)

- **등급은 지금 E(최하), D 두 단계만.** 이후 C, B…로 확장 가능한 구조.
- **등급과 강화는 데미지 배율 하나만 올린다.** 연사/사거리/탄창 등 무기 개성은 그대로.
  - E+0 100%, 강화 1단계당 +2%, E+5 110% / D+0 110%, D+5 120%.
- **강화** +1~+5: 골드 소모, 단계가 오를수록 성공률 하락(예: 90% → 50%). **실패해도 골드만 잃고 무기는 안 깨진다.**
- **합성**: 같은 계열 E등급 +5 무기 2개 → 같은 계열 D등급 1개.
- D등급 다이아 직접 구매 버튼은 만들되 결제 연동 전까지 비활성.
- 보유 무기는 개체 단위로 저장(같은 무기 여러 개 보유 가능): `users/{uid}/weapons/{id}` = { weaponId, grade, level }.

## 8. 캐릭터

- 캐릭터마다 능력치가 있다. 다이아로 구매, 강화 +1~+5(무기와 같은 방식, 실패해도 안 깨짐).

| 캐릭터 | 체력 | 명중 | 회피 | 크리티컬 | 이동 | 강화 1단계마다 |
|---|---|---|---|---|---|---|
| 기본 병사(무료) | 100 | 0 | 0 | 0 | 100% | 체력 +2 |
| 저격수형 | 95 | +8 | 0 | 0 | 100% | 명중 +1 |
| 정찰형 | 90 | 0 | +8 | 0 | 105% | 회피 +1 |
| 강습형 | 95 | 0 | 0 | +5%p | 100% | 크리티컬 +1%p |

## 9. 재화와 경제 [수치 잠정, 전부 설정값으로]

- **골드**: 플레이로 획득. 무기 구매, 강화, 합성.
- **다이아**: 지금은 골드 환전으로만 획득(나중에 결제 추가). 캐릭터, D등급 직접 구매 등.
- 환전: **골드 100,000 → 다이아 100** (1다이아 = 1,000골드). 골드 → 다이아 한 방향만.
- 매치: 승리 5,000 / 패배 2,500 / 킬당 200.
- 보상형 광고: 10,000골드, **1시간 쿨타임(서버 시간 기준)**. 하루 횟수 제한은 설정값으로 두고 기본은 제한 없음.
- 가격: E등급 무기 20,000 / 강화 2,000 → 10,000(단계별) / 합성 15,000 / 캐릭터 300다이아.
- 재화를 클라이언트가 쓰는 구조라 조작 가능성은 인정. Firestore 보안 규칙으로 본인 문서만 수정 가능하게.

## 10. 수익화

- **인앱 결제**: 판매자 프로필이 없어 상품 등록 불가. 상점 UI + `in_app_purchase` 연동 코드까지만 만들고 결제 버튼은 "준비 중"으로 막는다.
- **AdMob 보상형 광고**만 사용. **매치 밖에서만** 노출(결과 화면, 상점 등). 개발 중엔 Google 테스트 광고 ID만. Play Console에 광고 포함 신고.
- 광고 보상 후보: 매치 보상 2배, 무료 보급상자, 무기 체험권(1판), 부스터 무료권.

## 11. 맵

- **기본은 진영전**: 우리 진영(A)과 상대 진영(B)이 맵 양 끝. 리스폰은 항상 자기 진영.
- **180도 회전 대칭**, **세 갈래 길**(중앙 근접전 구역 + 양옆 장거리 통로).
- 스폰 보호 3초 무적, 진영 입구에 높은 벽(진영 안 직접 사격 방지).
- Tiled로 제작, 오브젝트 레이어에 `spawn_A`, `spawn_B`.
- 랜덤 스폰은 별도 모드로만.

## 12. 모드와 매치

- 우선순위: **PvP 1대1** → 훈련소(봇 + 튜토리얼) → PvP 2대2(빈자리 봇) → 좀비전(시야 제한) → 3대3.
- 코드는 처음부터 N명 구조.
- 방 입장: 방 코드 [잠정: 4자리].
- 매치 규칙 [잠정]: 팀 데스매치 3분, 20킬 선취 시 종료.
- 사망 후 부스터 [잠정]: 5초 동안 3개 중 1개 선택(강화탄 공격력 +20% / HP UP +30 / 투시경 10초). 원작은 10초 동안 최대 2개.
- 분노 시스템(많이 죽을수록 체력·공격력 상승, 원작 요소)은 2차. 능력치 격차 완화용으로 우선순위 상향 검토.

## 13. 멀티플레이와 데이터

- **Realtime Database**(asia-southeast1): 자기 상태를 초당 15회 기록, 상대 상태는 보간해서 그림.
- **판정 = DB 트랜잭션**: 맞힌 쪽이 `hp/{상대}`를 트랜잭션으로 깎는다. HP를 0 이하로 만든 요청이 킬. 점수도 트랜잭션. 죽은 쪽이 리스폰 시 자기 HP 복구. `onDisconnect`로 접속 끊김 기록.
- 클라이언트 판정이라 치트 가능 → 과제 범위에선 허용, 발표에서 서버 판정을 개선 방향으로 제시.
- RTDB 구조:
  ```
  rooms/{code}/meta     { mode, hostUid, status, map, createdAt, endsAt }
  rooms/{code}/players/{uid} { name, team, ready, connected, character, primary, secondary }
  rooms/{code}/states/{uid}  { x, y, a, stance, up, t }
  rooms/{code}/hp/{uid}      (트랜잭션)
  rooms/{code}/shots/{id}    연출용
  rooms/{code}/kills/{id}    { killer, victim, weapon, crit, t }
  rooms/{code}/score         { A, B } (트랜잭션)
  ```
- **Firestore**: `users/{uid}` { nickname, gold, diamond, lastAdAt(서버 시간), fcmToken, stats }, `users/{uid}/weapons/{id}`, `users/{uid}/characters/{id}`, `matches/{id}`, `config/balance`(밸런스·경제 설정).
- 로그인 [잠정]: 익명 로그인 + 닉네임.
- 테스트: 에뮬레이터 1개 + 크롬 1개로 1대1, 나머지는 봇. Firebase 로컬 에뮬레이터 사용.

## 14. 기술과 아키텍처

- Flutter + Flame + flame_tiled, Riverpod 3(코드 생성 없음) + flame_riverpod.
- Flutter 공식 아키텍처(MVVM + Repository + Service) + `rules/` 순수 Dart 계층. 자세한 건 `CLAUDE.md`.
- Firebase: Auth, Realtime Database, Firestore, Cloud Messaging. Spark(무료) 요금제 기준.
- Git: GitHub Flow(main 하나 + 기능 브랜치, 스쿼시 병합, 배포는 태그).

## 15. 우선순위

1. 인게임: 조작, 자세, 엄폐물, 진영 맵, 1대1 PvP, 무기 시스템(계열당 1개), 등급 배율 자리
2. 무기 늘리기(계열당 3~4개), 캐릭터
