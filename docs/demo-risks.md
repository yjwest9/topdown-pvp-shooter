## 수정 2 (2026-10-15, fix/demo-hardening)

- 오판 방지: `_checkStuck`의 두 판정(내 연결 표시 꺼짐, 방장 끊김)은 3초(`stuckGraceMs`) 넘게 그대로일 때만 끝낸다. 오판이 **실제로 있었다**: 방장의 `connected`가 아직 안 써진 시작 직후엔 참가자가 방장이 나간 걸로 보고 바로 승리로 끝냈고, 내 표시가 잠깐 꺼졌다 켜져도 바로 패배로 끝냈다(테스트가 실패, 유예를 넣어 통과, 유예를 0으로 하면 다시 실패).
- 6: 오프라인 첫 실행 뒤 온라인이 되면 홈이 3초마다 프로필을 다시 읽어 없으면 닉네임 창을 띄운다(Riverpod 자체 재시도는 약 40초 뒤 포기해서 그 뒤엔 영영 안 돌아왔음). 연결 실패 화면은 영어 원문 대신 "인터넷 연결을 확인해 주세요"(원문은 로그).

## 수정 3 — 재연결 조사 (2026-10-15, fix/demo-hardening)

DB 연결 상태(`.info/connected`)를 시각과 함께 로그(`[conn]`)로 남겨서 데이터를 껐다 켰다(`adb shell svc data`, 와이파이는 끈 채).

| 모드 | 데이터 끔 | 데이터 켬 | 결과 |
|---|---|---|---|
| 실서버(디버그 앱, asia-southeast1) | 즉시 `connected=false` | 약 6~8초 뒤 `connected=true` | **스스로 다시 붙음** |
| 로컬 에뮬레이터 모드(USE_EMULATOR) | 즉시 `connected=false` | 90초 넘게 `false` 그대로 | **스스로 안 붙음** |

- 로컬 모드에서 `goOffline` → `goOnline`(0초·0.5초 간격 둘 다), 와이파이 켜기·끄기, 앱을 홈으로 보냈다 다시 열기를 해도 안 붙었다. 이때 앱에서 `10.0.2.2:9000`으로 가는 TCP 연결 시도 자체가 하나도 없었고(`/proc/net/tcp`), 같은 시각 셸에서는 `10.0.2.2:9000`에 연결됐다. 로그인 토큰을 새로 받아 보게 해도 같았다. 원인은 못 찾았다(로컬 모드에서만 쓰는 `FirebaseDatabase.instanceFor(databaseURL: http://10.0.2.2:9000)` 경로 때문으로 의심, 미확인).
- 그래서 사용자가 본 "로컬 모드에서 연결이 끊긴 뒤 아무것도 안 됨"은 **로컬 에뮬레이터 모드 전용 현상**이다. 실서버(= Play 배포 앱과 같은 경로)에서는 6~8초 안에 스스로 돌아온다. 로컬 모드에서는 네트워크가 한 번이라도 끊기면 **앱을 다시 시작**해야 한다.
- 고친 것(시연 안전용, 로컬·실서버 공통): 연결이 안 돼 있을 때 기다리지 않고 알린다. 빠른 대전·방 만들기·입장·광고 보상은 시작 전에 `.info/connected`를 보고, false면 재연결을 한 번 시도하고 3초 안에 안 붙으면 "인터넷 연결을 확인해 주세요"(광고는 광고를 보여 주기 전에, 광고를 보는 동안 끊겼으면 보상 직전에 다시 확인). 앱이 다시 앞으로 올 때도 끊겨 있으면 재연결을 시도한다. 실서버에서는 데이터를 끈 채 빠른 대전 → 3초 안에 한국어 문구, 데이터를 켜고 약 8초 뒤 빠른 대전 → 앱 재시작 없이 대기석이 써지는 것을 직접 확인(테스트 데이터는 삭제).
- 사용자가 본 "광고 중 데이터를 껐는데 문구가 안 뜸 / 다시 켜도 보상이 안 들어옴": 로컬 모드에서 연결이 안 돌아오는 것 + 쓰기가 오류 없이 기다리던 것의 합이었다. 이제 끊긴 걸 보면 바로(광고 전엔 3초 안에, 보상 직전엔 3초 안에) 알린다.
- 상대 이탈 승리도 유예 적용: 방장의 `_checkEnd`가 상대 연결 표시가 꺼지자마자 meta에 끝을 써서 잠깐 끊겼다 돌아온 쪽이 졌다고 나오던 경로가 있었다(상대 이탈은 이제 `_checkStuck`만 3초 유예 뒤 처리). 강제 종료는 3초 늦게 끝난다.

## 9. FCM 푸시 시연 방법 (코드·docs/push.md로 확인, 발송은 안 함)

- 앱은 안드로이드에서 시작할 때 알림 권한을 묻고 **토픽 `holiday_event`** 를 구독한다(`lib/data/services/push_service.dart`의 `eventTopic`). 웹은 구독하지 않는다.
- 보내는 법: Firebase 콘솔 → 프로젝트 `topsoldier` → Messaging → 새 캠페인 → Firebase 알림 메시지 → 제목·내용 입력(예: "오늘은 한글날!" / "매치 보상 2배 이벤트가 시작됐어요.") → 타겟 **주제(Topic) = `holiday_event`** → 예약 "지금" 또는 맞춤 일정(Asia/Seoul) → 게시.
- **앱이 화면 앞에 떠 있으면 알림이 안 뜬다**(앞 화면 알림 처리 코드가 없음, docs/push.md에도 같은 설명). 발표 때는 앱을 홈 버튼으로 백그라운드에 보낸 뒤 보내야 상단 알림이 보인다. 이때 위 3·3-1처럼 매치 밖(홈 화면)에서 하는 게 안전.
- 구독은 앱 설치 후 처음 실행할 때 이뤄지고 서버 반영에 몇 분 걸릴 수 있으니 **발표 전날 미리 한 번 실행**해 둔다. 에뮬레이터는 Google Play 이미지여야 FCM을 받는다.
