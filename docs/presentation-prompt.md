## 발표 조건
- 국비과정 마지막 개인 프로젝트 **중간(초안) 제출용**, 최종 발표는 2026-10-22(목).
- 발표 시간 **10분 이내** (질의응답 제외). 슬라이드 약 16장, 본문 슬라이드는 장당 30~40초.
- 청중: 교수님과 수강생. 비전공자도 이해할 수 있게 쉬운 말.
- 디자인: 깔끔하고 단순하게. 어두운 배경(진한 남색/검정) + 포인트 색 1개(주황 또는 연두). 글자는 크게, 한 장에 핵심 3~4줄 이하. 장식 최소.
- 한국어. 슬라이드마다 **발표자 노트(말할 내용 2~3문장)**를 함께 작성.
- 이미지가 필요한 자리는 `[이미지: 설명]`으로 표시 (내가 스크린샷을 넣는다).

## 슬라이드 구성 (이 순서 그대로)
목차 슬라이드와 **섹션 구분 슬라이드**(큰 번호 + 섹션 제목 + 한 줄 설명만, 배경 다르게)를 반드시 넣는다.

1. **표지**: TOP SOLDIER / 2D 탑다운 실시간 PvP 슈터 / 서영준 / 2026.10.22
2. **목차**: 1. 프로젝트 소개 / 2. 게임 소개 / 3. 기술 구성 / 4. 개발 과정과 배포 / 5. 마무리
3. **[구분] 1. 프로젝트 소개**
4. **기획 의도**
   - 2015~2020 서비스한 모바일 FPS에서 영감을 받은 **오리지널** 게임 (이름·로고·그래픽은 쓰지 않음)
   - 핵심은 PvP: 내 폰과 상대 폰이 실시간으로 맞붙는다
   - 목표: Google Play 비공개 테스트 배포까지 (최소 Android 7(API 24), Android 12(API 31) 에뮬레이터에서 동작 확인, 타깃 API 36)
5. **과제 필수 요건 충족표** (표 형태)
   | 요건 | 우리 프로젝트 |
   |---|---|
   | Open API | 한국천문연구원 특일정보 API → 공휴일이면 보상 2배 이벤트 |
   | 푸시 알림 | Firebase Cloud Messaging (이벤트 알림) |
   | Firebase | Auth(익명 로그인) + Realtime Database(실시간 대전·프로필) |
   | REST·JSON | 공휴일 API 호출·파싱 |
   | MVVM | UI / ViewModel / Repository / Service 계층 |
   | 테스트·배포 | 자동 테스트 488개, Play Console 비공개 테스트 |
6. **[구분] 2. 게임 소개**
7. **게임 방법** (스크린샷 중심)
   - 왼쪽 화면: 조이스틱 이동(끝까지 밀면 달리기) / 오른쪽 화면: 드래그로 시점 회전
   - 버튼: 점프, 앉기, 사격, 재장전
   - 3분 안에 **먼저 7킬** 하면 승리
   - [이미지: 인게임 화면 + 조작 UI 표시]
8. **게임 특징**
   - 자세 시스템: 서기·앉기·점프·달리기마다 속도와 탄 퍼짐이 다름
   - 엄폐물: 낮은 상자는 앉으면 숨고, 점프하면 넘고, 높은 벽은 시야를 막음
   - 총기 11종(라이플·저격·샷건·권총), 총마다 소리·모양·성능이 다름
   - 캐릭터 4종(기본 병사·저격수·정찰병·돌격병), 능력치가 다름
   - 성장: 골드로 무기·캐릭터 강화(+0~+5), 확률 상한으로 격차 제한(최대 성장 격차 총알 2발 이내)
   - [이미지: 무기 화면, 캐릭터 화면]
9. **게임 모드와 맵**
   - 빠른 대전(자동 매칭) / 친선전(방 코드 입장) / 봇전(난이도 3단계) / 훈련소
   - 맵 2종: 1대1 전용 duel(17×17칸), 다대다용 outpost(31×31칸, 세 갈래 길)
   - 봇전·친선전 맵 선택(1대1 duel 17×17 / 다대다용 outpost 31×31). 빠른 대전은 duel 고정
   - [이미지: 두 맵 미리보기(docs/maps/duel.png, outpost.png), 미니맵]
10. **경제와 수익화**
    - 골드/다이아, 상점 환전, 보상형 광고(1시간마다 10,000G, AdMob 테스트 ID)
    - 결과 화면에서 보상형 광고를 보면 그 판 골드 2배(판당 1회)
    - 공휴일 이벤트: Open API로 오늘이 공휴일인지 확인 → 보상 2배
11. **[구분] 3. 기술 구성**
12. **기술 스택과 아키텍처**
    - Flutter + Flame(게임 엔진) + Riverpod 3 / Firebase(Auth·Realtime DB·FCM) / AdMob
    - 구조 그림: `UI(View·ViewModel)` → `Repository` → `Service(외부 연결)` + `rules`(순수 Dart 게임 규칙·밸런스) + `game`(Flame)
    - [다이어그램: 계층 화살표. ui/game → repositories → services, rules는 독립]
13. **실시간 대전 동기화**
    - 방장(Host)이 매치 진행을 관리, 각자 자기 위치·총알·재장전 상태를 Realtime DB에 전송
    - 상대 화면은 보간(interpolation)으로 부드럽게 표시
    - 끊김 대비: 3초 유예 후 판정, 재연결 안내, 방장 이탈 시 매치 종료 처리
    - [다이어그램: 폰A ↔ Firebase ↔ 폰B]
14. **품질 관리**
    - 규칙(rules)은 테스트 먼저 작성, 자동 테스트 **488개** 통과
    - 밸런스 불변식 테스트: 크리티컬 ≤30%, 미스 0~20% 등
    - DB 보안 규칙 61개 항목을 Firebase 로컬 에뮬레이터로 검증
    - 릴리스 빌드(R8 축소) 실행 확인으로 출시 전 크래시 발견·수정
15. **[구분] 4. 개발 과정과 배포**
16. **개발 일정** (타임라인)
    - 10/7 첫 빌드 Play 비공개 테스트 업로드 → 10/14 1대1 완성 → 10/15 1대1 전용 맵·효과음·그래픽 → 10/22 최종 발표
    - 버전 0.1.0 → 0.1.6까지 6회 업로드(0.1.4는 건너뜀), 커밋 53개
17. **배포 현황**
    - Google Play 비공개 테스트 진행 중, 최소 지원 **Android 7(API 24)**, Android 12(API 31) 에뮬레이터에서 동작 확인, 타깃 API 36
    - 테스터 현재 9명 / 목표 12명 (12명 충족 후 14일 테스트 시작)
    - 광고·데이터 보안·개인정보처리방침 신고 완료
18. **개발하며 해결한 문제** (3개, 한 줄씩 원인 → 해결)
    - 릴리스 앱이 시작하자마자 종료: R8이 WorkManager 클래스를 삭제 → 보존 규칙 추가
    - 동시에 나갈 때 결과 화면이 멈춤: 방 삭제 권한 거부 → 실패를 무시하고 화면 전환
    - 에뮬레이터 렉 11fps: 측정 결과 HUD 글자 그림자 blur가 원인(실제 폰은 별도 확인)
19. **시연** (영상 1분) [목요일 전 채울 것: 시연 영상 녹화본 삽입 — 빠른 대전 한 판]
20. **앞으로의 계획 / 마무리**
